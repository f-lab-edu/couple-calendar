# Product 논의 로그 — Couple Calendar
_최종 갱신: 2026-06-26_

## 제품 현황
커플이 일정·기념일·중요한 순간을 함께 관리하는 공유 캘린더 앱. **2026-06 App Store v1.0 정식 출시(READY_FOR_SALE), iOS 전용·한국어·무료.** 구조는 RN WebView host(react-native-instant-webview)가 Next.js 웹앱을 감싸고, 백엔드는 Kotlin/Spring Boot + Supabase(PostgreSQL), GCP Cloud Run. 핵심 가치는 "둘의 일상 공유".

출시본 구현 기능: 공유 캘린더(일정 CRUD·카테고리·월달력 스와이프·상대 일정 배지), 기념일+D-day, 커플 연결(초대코드·자동진행·공유시트), 인증(Apple/이메일·토큰 갱신), 푸시(리마인더+상대 활동 알림·알림 설정), 설정(시작일·프로필·연결끊기·약관).

## 결정된 것
- 2026-06-26: 로드맵 우선순위 프레임을 **기반(점검/측정) → 리텐션(위젯/푸시) → 획득(Android/ASO)** 순으로 합의 방향 설정. 커플 앱의 생사 지표는 dual-activation(둘 다 연결)과 푸시 신뢰성이라는 점을 핵심 전제로 둠.

## 다음 액션 (우선순위)
1. **리마인더 E2E 점검 + 출시 브랜치(feat/redesign-bold-b) main 병합 + 핵심 퍼널 측정 도입** — 방금 출시한 핵심 리텐션 루프(푸시)가 실기기에서 도는지 확인하고, 측정으로 다음 결정을 데이터화. 공수 작고 모든 후속 결정을 떠받침. 측정은 5단계만: 설치→로그인→초대→연결완료→7일 재방문.
2. **홈 위젯 (D-day + 다음 일정)** — 커플 앱 검증된 리텐션·감성 무기. 단 WebView 불가, WidgetKit 네이티브 + 새 빌드/심사 필수(최대 비용). #1 측정으로 리텐션 베이스라인 확인 후 베팅.
3. **Android 빌드** — TAM 약 2배 획득 카드. RN host라 비교적 저렴. 리텐션 검증 후 1순위 획득 카드로 승격.
4. (보류) 공유 메모/사진 — 가치 높으나 스토리지 비용·정책 부담, 코어 사용 데이터 본 뒤 결정.
5. (보류) 반복 일정 — 편의성 중간, 기념일은 이미 반복 지원.
6. ASO/랜딩 — 상시·저공수 획득, 획득 단계 진입 시 병행.

## 열린 질문
- 측정 도구가 현재 붙어 있나? (Firebase Analytics/Amplitude 등 — 활성화율·리텐션 가시성)
- dual-activation 실태: 초대받은 파트너의 실제 연결 전환율? 파트너 미연결 솔로 유저의 현재 경험은?
- Android 시급성: 마케팅 채널 계획상 급한가, iOS 리텐션부터 다져도 되는가? (답에 따라 Top 2를 위젯↔Android로 교체 가능)
- 사진/메모 도입 시 스토리지 비용·콘텐츠 정책 감당 범위?
